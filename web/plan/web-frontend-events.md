## Event

The Event interface represents an event which takes place on an EventTarget.

An event can be triggered by the user action e.g., clicking the mouse button or tapping the keyboard, or generated by APIs to represent the progress of an asynchronous task. It can also be triggered programmatically, such as by calling the HTMLElement.click() method of an element, or by defining the event, then sending it to a specified target using EventTarget.dispatchEvent().

There are many types of events, some of which use other interfaces based on the main Event interface. Event itself contains the properties and methods which are common to all events.

Many DOM elements can be set up to accept (or "listen" for) these events, and execute code in response to process (or "handle") them. Event-handlers are usually connected (or "attached") to various HTML elements (such as button, div, span, etc.) using EventTarget.addEventListener(), and this generally replaces using the old HTML event handler attributes. Further, when properly added, such handlers can also be disconnected if needed using removeEventListener().

When there are many nested elements, each with its own handler(s), event processing can become very complicated—especially where a parent element receives the very same event as its child elements because "spatially" they overlap so the event technically occurs in both, and the processing order of such events depends on the Event bubbling settings of each handler triggered.

## EventTarget
EventTarget is the foundation of the browser's event system.

It is an interface that provides three core methods:

addEventListener()
removeEventListener()
dispatchEvent()


Any object that can receive events or emit events implements EventTarget. Common examples include window, document, DOM elements, FileReader, WebSocket, and even custom classes you create.

The Big Picture
EventTarget
    │
    ├─ addEventListener()
    ├─ removeEventListener()
    └─ dispatchEvent()


You can think of an EventTarget as a publisher/subscriber system:

Publisher
    │
dispatchEvent()
    │
    ▼
EventTarget
    │
    ▼
addEventListener()
Subscribers

Example 1: HTML Element

A button is an EventTarget.

const button = document.querySelector("button");

button.addEventListener("click", () => {
    console.log("clicked");
});


Here:

button instanceof EventTarget


returns:

true


because all DOM elements inherit event functionality from EventTarget.

Example 2: Document
document.addEventListener(
    "click",
    () => console.log("Document Click")
);


document is also an EventTarget.

Example 3: Window
window.addEventListener(
    "resize",
    () => {
        console.log("resized");
    }
);


window implements EventTarget too.

Core Methods
addEventListener()

Registers a listener.

const handler = () => {
    console.log("Clicked");
};

button.addEventListener(
    "click",
    handler
);

removeEventListener()

Removes a previously registered listener.

button.removeEventListener(
    "click",
    handler
);

dispatchEvent()

Triggers an event.

button.dispatchEvent(
    new Event("click")
);


This executes all matching listeners immediately.

EventTarget Without HTML

The most interesting feature is that you can create your own event-driven objects.

const bus = new EventTarget();

bus.addEventListener(
    "message",
    e => {
        console.log("Received", e.detail);
    }
);

bus.dispatchEvent(
    new CustomEvent("message", {
        detail: {
            text: "Hello"
        }
    })
);


Output:

Received { text: "Hello" }


This turns bus into a simple event bus.

Internal Mental Model

Think of EventTarget as:

class EventTarget {

    addEventListener(type, fn) {
        // store callback
    }

    removeEventListener(type, fn) {
        // remove callback
    }

    dispatchEvent(event) {
        // execute callbacks
    }
}


The real implementation is much more sophisticated, but conceptually this is what it does.

Relationship Between Event and EventTarget

Many developers confuse them.

EventTarget = Who receives/sends events

Event = What happened


Example:

button.dispatchEvent(
    new Event("click")
);


Here:

button         → EventTarget
Event("click") → Event


Another example:

const userBus = new EventTarget();

userBus.dispatchEvent(
    new CustomEvent("user:login")
);

userBus               → EventTarget
CustomEvent(...)      → Event


A good way to remember it:

EventTarget is the object that owns the event system. Event is the message traveling through that system.

## web EventTarget.dispatchEvent()
EventTarget.dispatchEvent() is used to programmatically fire an event on a DOM element or any object that implements EventTarget (such as window, document, or custom event targets). It triggers the registered event listeners as if the event had occurred.

Basic Example
const button = document.querySelector("button");

button.addEventListener("click", () => {
  console.log("Button clicked!");
});

// Trigger the click event manually
button.dispatchEvent(new Event("click"));


Output:

Button clicked!


The click listener runs even though the user did not click the button.

Custom Events

You can create and dispatch your own events:

const div = document.getElementById("box");

div.addEventListener("userLoggedIn", (e) => {
  console.log(e.detail.username);
});

div.dispatchEvent(
  new CustomEvent("userLoggedIn", {
    detail: { username: "Arvind" }
  })
);


Output:

Arvind

Return Value

dispatchEvent(event) returns:

true if the event was not canceled.
false if the event is cancelable and an event handler called event.preventDefault().
Important Difference

Native browser events are typically queued and processed through the event loop, while dispatchEvent() invokes matching event handlers synchronously and completes before the next line of code runs.

button.dispatchEvent(new Event("click"));
console.log("After dispatch");


The click handler executes before "After dispatch" is logged.

Common uses:

Trigger UI actions programmatically.
Build custom event systems.
Notify components about state changes.
Testing event-driven code.

## full example of building custom event systems using event for web.

Below is a complete real-world custom event system for the web using EventTarget, CustomEvent, and dispatchEvent(). The architecture is similar to what large applications use internally. EventTarget provides the standard event API (addEventListener, removeEventListener, dispatchEvent), while CustomEvent allows data to be passed between independent modules.

├─ UserService.js

├─ Dashboard.js
└─ index.js

1. EventBus

A centralized event bus.

// EventBus.js

export class EventBus extends EventTarget {

    emit(eventName, payload = {}) {

        return this.dispatchEvent(
            new CustomEvent(eventName, {
                detail: payload
            })
        );
    }

    on(eventName, callback) {
        this.addEventListener(eventName, callback);
    }

    off(eventName, callback) {
        this.removeEventListener(eventName, callback);
    }

    once(eventName, callback) {
        this.addEventListener(eventName, callback, {
            once: true
        });
    }
}

export const eventBus = new EventBus();

2. User Service

This service publishes events.

// UserService.js

import { eventBus } from "./EventBus.js";

export class UserService {

    login(username) {

        const user = {
            id: crypto.randomUUID(),
            username
        };

        console.log("User logged in");

        eventBus.emit("user:login", user);

        return user;
    }

    logout(user) {

        console.log("User logged out");

        eventBus.emit("user:logout", user);
    }
}

3. Notification Service

This service listens for events.

// NotificationService.js

import { eventBus } from "./EventBus.js";

export class NotificationService {

    constructor() {

        eventBus.on("user:login", (event) => {

            const user = event.detail;

            console.log(
                `Notification: Welcome ${user.username}`
            );

        });

        eventBus.on("user:logout", (event) => {

            const user = event.detail;

            console.log(
                `Notification: Bye ${user.username}`
            );

        });
    }
}

Why use a custom event system?

Instead of:

A calls B
B calls C
C calls D


you get:

A emits event

B listens
C listens
D listens


The modules stay independent, easier to test, easier to replace, and easier to scale. This event-driven style is one of the main reasons EventTarget, CustomEvent, and dispatchEvent() are useful in modern web applications.
